Project Genesis & Vision

Why This Fork Was Created

What began as a packaging utility for TheTom's TurboQuant fork evolved into a groundbreaking experiment in AI-directed systems programming on AMD hardware.

🛠 Phase 1: Automated Cross-Platform ROCm Builds

This repository originated with a clear, pragmatic purpose: to provide a turnkey automated build and CI/CD system for TheTom's pioneering TurboQuant fork (TheTom/llama-cpp-turboquant).

While TurboQuant introduced revolutionary KV cache compression (2 to 3.25 bits/value via Walsh-Hadamard Transform), running and building it on modern AMD ROCm environments was notorious for friction. On Windows 11, lack of pre-built portable binaries, compiler header conflicts between MSVC and Clang/HIP, and the transition to AMD ROCm Core SDK 10 ("TheRock") left AMD GPU users stranded.

We built automated GitHub Actions CI/CD workflows producing clean, portable fat binaries for both Windows 11 and Ubuntu Linux across modern AMD architectures (`gfx900` to `gfx1201`).

🤖 Phase 2: The AI Engineering Experiment (Gemini 3.8)

Once build automation was achieved, the active experiment/rdna-boosts branch embarked on a bolder exploration:
How far can an advanced AI coding model (Gemini 3.8) autonomously diagnose, optimize, and push low-level GPU systems code beyond traditional hand-tuned performance limits?

Rather than trivial refactoring, Gemini was tasked with deep systems engineering:

  • Diagnosing hardware execution bottlenecks on AMD RDNA 3 and RDNA 4 (gfx1100, gfx1200).
  • Eliminating branch divergence with constant 256-entry scale lookup tables in L1 cache.
  • Overcoming workgroup occupancy starvation by expanding MMVQ allocations from 1 warp to 8 warps (256 threads).
  • Fusing multi-pass warp reductions to cut shuffle barriers by 50% in the Walsh-Hadamard transform.
  • Protecting Windows systems from catastrophic WDDM paging latency collapse.

The outcome: a 2.60x speedup in autoregressive decode throughput on 27B models, +103.5% faster prompt prefill over Vulkan, and complete on-device 110k context support with zero precision degradation.

💾 1. TurboQuant Ultra-Compressed KV Cache & Weights

Shrink KV cache VRAM by up to 8x using Walsh-Hadamard orthonormal rotation before quantization.
TheTom + RDNA Tuned
TurboQuant applies a fixed 128x128 orthonormal Walsh-Hadamard rotation (GGML_OP_TURBO_WHT) to key/value cache vectors before quantization. This Gaussianizes outlier channels, enabling ultra-low bit quantization without quality loss:
  • turbo2 (GGML_TYPE_TURBO2_0): 2.0 bits per value for KV cache (extreme compression).
  • turbo3 (GGML_TYPE_TURBO3_0): 3.25 bits per value for KV cache (recommended balance).
  • turbo4 (GGML_TYPE_TURBO4_0): 4.25 bits per value for KV cache (near-lossless fidelity).
  • TQ3_1S / TQ4_1S: 3-bit and 4-bit Lloyd-Max rotated weight types supported in llama-quantize.
PowerShell / Bash Inference with TurboQuant KV Cache
# Run large 65k context on a 16GB GPU with TurboQuant KV cache llama-cli -m models/Qwen3.8-27B-Q4_0_ROCMFP4_FAST.gguf \ -c 65536 \ -ngl 99 \ --cache-type-k q8_0 \ --cache-type-v turbo3 \ -fa 1
💡 Environment Tuning Knobs

TURBO_LAYER_ADAPTIVE=7: Boundary-layer precision allocation (preserves standard q8_0 precision on input/output boundary layers while utilizing turbo in the deep middle layers).
TURBO_AUTO_ASYMMETRIC=1: Automatically pairs higher-precision K cache with compressed V cache for models with high GQA ratios.

⚡ 2. Native ROCmFPX / ROCmFP4 Quantization Family

Sub-byte floating point formats tailored specifically for AMD RDNA and CDNA hardware.
Charlie + RDNA Boosts
Unlike generic integer K-quants designed for CPU/NVIDIA instruction sets, ROCmFPX uses micro-scaled floating point formats (UE4M3) that execute natively on AMD Compute Units:
  • Q4_0_ROCMFP4_FAST: Sub-byte 4-bit format accelerated by a 256-entry branchless scale LUT. Delivers 2.60x faster decode (17.77 t/s) on RX 9060 XT with 2.1 GB weight VRAM reduction.
  • Q2_0_ROCMFPX_AGENT: 2.75 bpw agent quantization that preserves Q6_K on attention heads and token embeddings while routing bulk feed-forward layers to 2-bit ROCmFP, keeping reasoning stable.
  • Q1_0_ROCMFPX_AGENT: Experimental 1.50 bpw prototype utilizing dual UE4M3 micro-scales.
PowerShell / Bash Creating ROCmFP4 Models & Launching GUI
# 1. Quantize a model directly with llama-quantize llama-quantize models/Qwen3.8-27B-F16.gguf models/Qwen3.8-27B-ROCMFP4.gguf Q4_0_ROCMFP4_FAST # 2. Or launch our native PowerShell WPF GUI with live GPU telemetry powershell -ExecutionPolicy Bypass -File .\scripts\quantize-rocmfpx-gui.ps1

⚙ 3. Gemini-Engineered RDNA 3 & RDNA 4 Kernel Suite

Deep hardware-level HIP and assembly optimizations eliminating GPU execution stalls.
Gemini 3.8 Boosts
Our fork includes 5 core kernel optimizations in the experiment/rdna-boosts branch designed specifically for AMD RDNA 3 (gfx1100) and RDNA 4 (gfx1200):
  • Branchless 256-Entry Scale LUT (rocmfp4_hip_scale.cuh): Replaces IEEE-754 exponent bitfield extraction and conditional branches with a 1-cycle constant memory scalar broadcast load instruction.
  • 8-Warp Wave-Cooperative MMVQ (mmvq.cu): Expands workgroup allocation from 1 warp (32 threads) to 8 warps (256 threads) under RDNA 3 and 4, preventing Dual Compute Unit starvation during decode.
  • Fused WHT Prerotate Reductions (mmvq-tq.cu): Merges sequential amax and sum shuffle loops into a single unrolled 5-step reduction, halving warp synchronization latency.
  • Native Wave-32 Hardware Ballot (set-rows.cu): Uses hardware __ballot instructions to gather wave-wide sign bits in a single cycle for Turbo3 packing.
  • Non-Temporal Streaming Stores (ggml_cuda_stcs): Bypasses L1 cache pollution during KV cache insertion to keep critical model weights in cache.

🚀 4. Speculative Decoding & MoE Reasoning Accelerators

Integrated advancements from Strata and Hipfire for high-speed multi-token generation.
Strata + Hipfire
State-of-the-art speculative drafting and Mixture-of-Experts inference controls:
  • Coupled Speculative Drafting with Gumbel-Max Sampling (--spec-gumbel): Couples pseudo-random SplitMix64 Gumbel noise across target and draft models, keeping acceptance rates high during temperature-based creative sampling.
  • Online Learned MoE Profile Auto-Saving (--moe-expert-profile-save): Dynamically records expert activation hits during runtime and writes a binary profile on context free, eliminating offline profiling steps.
  • Dynamic Cumulative Log-Probability Pruning (--draft-cutoff-logw): Prunes speculative draft proposals early when branch confidence drops below a threshold (e.g. -4.0), preventing wasted target verification compute.
  • Prompt Normalization Pipeline (--prompt-normalize): Strips runaway newlines, trailing whitespace, and non-breaking spaces to stop BPE token fragmentation that hurts draft acceptance rates by up to 24%.
  • MTP Draft Vocabulary Subsetting (--draft-vocab): Limits multi-token prediction heads to the top-N active vocabulary items.
PowerShell / Bash Accelerated Speculative Inference
# Run speculative drafting with coupled Gumbel sampling, prompt normalization, and cutoff pruning llama-cli -m models/Target-27B.gguf \ -md models/Draft-1.5B.gguf \ --spec-gumbel 1 \ --temp 0.7 \ --prompt-normalize \ --draft-cutoff-logw -4.0 \ --draft-vocab 4096

🛡 5. Windows WDDM Paging Protection & Memory Safeguards

Prevent catastrophic 7-10x decode latency collapse on Windows 11 systems.
Strata + Unsloth
On Windows 11, when GPU allocations approach total VRAM, the Windows Display Driver Model (WDDM) silently pages tensors into system RAM. This causes an invisible 7x to 10x latency collapse. Our fork introduces active safeguards:
  • WDDM Safety Reserve Guard (--vram-reserve-mib 512): Enforces a dedicated discrete GPU headroom reserve, warning prominently before transparent paging begins.
  • MTP Draft Compute-Buffer Capping (MTP_DRAFT_N_UBATCH=512): Prevents draft models from pre-allocating gigabytes of encoder buffer space for the full target ubatch.
  • Unsloth Contiguous Run Virtual Memory Mapping: Eliminates fragmentation and accelerates initial tensor mapping on SSDs.
PowerShell / Bash Safeguarding VRAM Headroom
# Enforce a 512 MiB discrete GPU headroom reserve llama-cli -m models/Qwen3.8-27B.gguf \ -c 16384 \ --vram-reserve-mib 512

Getting Started & Installation

Deploying this fork on Windows 11 and Ubuntu Linux is streamlined through pre-built releases and native build scripts.

📦 1. Download Pre-Built Releases

Grab ready-to-run release packages from our GitHub Releases page. Each release contains all portable ROCm DLLs, llama-cli, llama-server, llama-quantize, and GUI scripts:

  • Universal AVX2 Builds (llama-rocm-experimental-windows.zip / -linux.zip): Standard compatibility across all modern x86-64 CPUs.
  • Specialized AVX-512 Builds (llama-rocm-experimental-avx512-windows.zip / -linux.zip): Compiled with AVX512F, VBMI, VNNI, and BF16 for AMD Zen 4 / Zen 5 (e.g. Ryzen 9 9950X3D, 7000/9000 series) and modern Intel CPUs. Accelerates hybrid CPU+GPU offloading (e.g. Qwen 3.8 Flash-Next 51B, 70B+ models exceeding VRAM) and speeds up model quantization by 2x-3x!
📦 Browse GitHub Releases

⚙ 2. Building from Source (CMake & Ninja)

Build natively using AMD ROCm 10 / 10.1 (TheRock) via our automated script or manual CMake:

PowerShell / CMake / Ninja (ROCm TheRock) Native Build
# Option A: Automated PowerShell build script (prompts for AVX2 or AVX-512) .\build.ps1 # Or build specialized AVX-512 directly: .\build.ps1 -Avx512 # Option B: Manual CMake build targeting AMD RDNA4 (gfx1200) cmake -B build -G "Ninja" -DGGML_HIP=ON -DAMDGPU_TARGETS="gfx1200" -DCMAKE_BUILD_TYPE=Release # For AVX-512, append: -DGGML_AVX512=ON -DGGML_AVX512_VBMI=ON -DGGML_AVX512_VNNI=ON -DGGML_AVX512_BF16=ON cmake --build build --config Release
