1. MMQ Dispatch & Native FP4 Prefill

During initial testing, ROCmFP4 suffered an 82 t/s prompt bottleneck. Root-cause analysis revealed that while decoding used fused WMMA kernels, batch prompt processing ($N > 8$) defaulted to cublasGemmEx, triggering on-the-fly FP16 dequantization for all 27B weights on every step. Registering ROCmFPX in ggml_cuda_should_use_mmq routed GEMM workloads directly to native compiled MMQ kernels, unlocking 302.58 t/s in dense sweeps and up to 806.49 t/s peak.

2. Dual-Issue Wave32 Execution on RDNA4

AMD RDNA4 compute units (gfx1200) execute in 32-thread wavefronts with dual-issue SIMD pipelines. Our experimental fork replaces legacy inline PTX/GCN assembly with native compiler intrinsics (__builtin_amdgcn_wmma, __builtin_amdgcn_fdot2, and __builtin_amdgcn_perm), allowing the LLVM/Clang 23 scheduler to interleave matrix multiply and scale operations with zero pipeline stalls, boosting decode to 19.85 t/s (2.43x faster).

3. Multi-Token Prediction (MTP) Speculation

Qwen 3.8 features hyper-connection prediction heads that generate up to 3 speculative candidate tokens per forward pass. Because verification and draft generation share KV cache state on GPU, speculation incurs near-zero overhead. On structured code generation, acceptance rates reach 63.4% with mean accepted length exceeding 2.89 tokens, generating up to 4 tokens per step.

4. TurboQuant Polar Walsh-Hadamard KV Cache

Standard F16 KV cache consumes 16 MiB per 1,000 tokens for Qwen 3.8 27B, quickly overwhelming 16GB cards beyond 12k context. TurboQuant applies a fast orthonormal Walsh-Hadamard rotation (GGML_OP_TURBO_WHT) before quantizing vectors to 3.25 bits (turbo3), Gaussianizing outliers and preserving perplexity while slashing KV cache memory by 79%. This enables 64k+ context windows on consumer GPUs.
