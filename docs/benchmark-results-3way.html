1. MMQ Prefill Dispatch Fix

During initial benchmarks, ROCmFP4 suffered an 82 t/s prompt throughput bottleneck. Root-cause profiling showed that GEMM workloads ($N > 8$) defaulted to cuBLAS with on-the-fly FP16 dequantization. Registering ROCmFPX in ggml_cuda_should_use_mmq routed batch execution directly to native compiled MMQ kernels, unlocking 806.49 t/s peak prefill (3.35x faster than Upstream).

2. Dual-Issue Wave32 WMMA Execution

AMD RDNA4 compute units (gfx1200) execute in 32-thread wavefronts with dual-issue SIMD pipelines. Our experimental fork replaces legacy inline PTX/GCN assembly with native compiler intrinsics (__builtin_amdgcn_wmma, __builtin_amdgcn_fdot2, and __builtin_amdgcn_perm), allowing the Clang 23 scheduler to eliminate pipeline stalls and double decode speed to 19.65 t/s.

3. Multi-Token Prediction (MTP) Dynamics

Qwen 3.8's integrated MTP heads generate up to 3 speculative candidate tokens per forward pass. Under greedy decoding, acceptance reaches 86.5% with 3.50 tokens/step on Upstream. Under realistic sampling (temp=0.6), acceptance settles to ~22.4%, where ROCmFP4's raw 2x memory bandwidth produces an industry-leading 21.14 t/s generation speed.

4. TurboQuant Polar Walsh-Hadamard KV Cache

Standard F16 KV cache consumes ~213.5 MiB per 1,000 tokens for Qwen 3.8 27B, causing immediate OOM crashes above 4,096 tokens on a 16GB GPU. TurboQuant applies a fast orthonormal Walsh-Hadamard rotation (GGML_OP_TURBO_WHT) before quantizing to 3.25 bits (turbo3), enabling 65,536+ tokens (64k context) without perplexity degradation.
