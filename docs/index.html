⚡ DFlash2 Block Diffusion Architecture, Pipeline Fusions & The Discrete GPU Tradeoff

1. Fused Encoder & Single-Sync Sampler Pipeline: By fusing the DFlash encoder directly into KV injection decode and adopting a single-synchronization sampler view (porting upstream PRs #27310 & #30196), we eliminated redundant GPU forward passes, intermediate D2H memory copies, and repeated device synchronizations per speculative candidate. This lowered per-step dispatch latency across the board, pushing peak code generation up to 21.57 t/s (57.3% acceptance rate) and elevating creative prose above bare decode (18.15 t/s vs. 18.33 t/s).
2. Confidence Gating (--spec-draft-p-min 0.6) Tames Speculative Wastage: In deep drafting mode (n=7) and adaptive mode, pruning speculative branches whenever draft confidence falls below 60% caused acceptance rates to surge from 22.9%-29.8% up to 50.0% - 56.5% (Fixed n=7) and 63.7% - 71.2% (Adaptive), cutting discarded draft tokens by over 50%.
3. Why DFlash Gains Differ from MTP on Discrete GPUs: Unlike MTP (Multi-Token Prediction), which computes draft tokens using a lightweight linear head within the base model's existing attention context, DFlash2 is an external 1.03 GB non-autoregressive block diffusion network. On a discrete GPU with a 128-bit memory bus where bare decode takes only 54 ms per token, running repeated graph dispatches for an external draft network incurs significant scheduling and bus overhead. As a result, short draft depths (Fixed n=3) represent the empirical sweet spot on discrete GPUs, delivering up to +18.7% higher throughput on structured generation without dispatch overhead.

1. Zero Quantization Loss: On 129 chunks (66,048 tokens), Qwen3.8-27B-Q4_K_M achieves PPL = 7.8806 (+/- 0.1129), while our optimized Qwen3.8-27B-Q4_0_ROCMFP4_FAST achieves PPL = 7.8766 (+/- 0.1120). ROCmFP4 yields a -0.05% relative delta (identical/slightly superior accuracy), conclusively disproving any degradation from FP4 weights or TurboQuant KV compression!
2. WDDM Memory Pressure Resolution: Because Q4_K_M takes 15.1 GB on GPU, it triggers low VRAM headroom warnings (0 MiB free), causing Windows WDDM to page memory and slowing passes to 12.46 seconds. ROCmFP4 has 2,559 MiB free VRAM headroom, accelerating eval passes to 8.08 seconds (1.54x faster)!

💾 Empirical Context Limits & TurboQuant KV Cache Compression

Empirical boundary probing on hardware (AMD Radeon RX 9060 XT, 16,304 MiB VRAM) established the exact context capacity before Windows WDDM paging triggers system RAM spillover:

  • Q4_K_M + FP16 KV: 14,848 tokens max (1,077 MiB KV, +1 MiB headroom; 15,104 tokens spills by -14 MiB).
  • Q4_K_M + TurboQuant KV: 35,840 tokens max (963 MiB KV, +9 MiB headroom; 36,352 tokens spills by -4 MiB).
  • ROCmFP4_FAST + FP16 KV: 47,104 tokens max (3,093 MiB KV, +51 MiB headroom; 48,128 tokens spills by -13 MiB).
  • ROCmFP4_FAST + TurboQuant KV: 110,592 tokens max (2,660 MiB KV, +44 MiB headroom; 112,640 tokens spills by -12 MiB).

TurboQuant KV compression (q8_0 K + turbo3 3.25-bit V cache) compresses KV memory from ~72.5 KB/token down to ~24.0 KB/token (3.0x - 3.2x compression). Combined with the 2,097 MiB weight savings of ROCmFP4, this expands context capacity by 7.45x (from 14,848 to 110,592 tokens) completely within 16GB VRAM without system RAM paging.

⚙ Kernel & Architectural Optimizations in Experimental Fork

Our fork incorporates specialized kernel optimizations designed specifically for AMD RDNA 4 (gfx1200) architecture and block diffusion speculative token prediction:

  • DFlash2 Block Diffusion Drafting: Leverages Qwen3.8-27B-DFlash2-Q4_0_ROCMFP4_FAST.gguf to predict token blocks from intermediate layer features, reaching 21.18 t/s and 57.3% acceptance rate on code generation.
  • Dynamic Adaptive Depth Controller (--spec-draft-adaptive): Dynamically bounds draft depth between 3 and 7 tokens based on rolling verify feedback, eliminating the "Entropy Cliff" on high-entropy prose.
  • Branchless Scale LUT (rocmfp4_hip_scale.cuh): Replaced runtime IEEE-754 bit-twiddling and branches with a 256-entry constant scale table residing in L1 cache, eliminating divergent control flow on HIP.
  • 8-Warp Wave-Cooperative MMVQ (mmvq.cu): Expanded threadblock allocation from 4 warps to 8 warps for RDNA 3 and RDNA 4, increasing CU occupancy and achieving 17.77 t/s decode.
  • Fused Prerotate Reduction (mmvq-tq.cu): Fused multi-pass loops into a single unrolled wave reduction, cutting register pressure and launch latency.
  • Constant Centroid Tables in Tile Loading (mmvq-tq.cu): Optimized WMMA tile loading with constant centroid lookup tables.
  • Native Wave Ballot Instructions (set-rows.cu): Utilized hardware __ballot instructions on AMD wave-32 architectures for Turbo3 sign packing.
  • TurboQuant Walsh-Hadamard Transform: Compresses KV vectors via 128x128 orthonormal WHT, enabling 110,592 context on 16GB VRAM with zero perplexity degradation.
