1. Native RDNA4 WMMA FP4 Execution

AMD RDNA4 compute units (gfx1200) execute in 32-thread wavefronts with dual-issue SIMD pipelines. Our experimental fork replaces legacy inline PTX/GCN assembly with native compiler intrinsics (__builtin_amdgcn_wmma_i32_16x16x16_iu4_w32_gfx12, __builtin_amdgcn_fdot2, and __builtin_amdgcn_perm), allowing Clang 23 to eliminate pipeline stalls and double decode speed to 14.61 t/s (2.08x speedup).

2. Vectorized Turbo K/V Loads in Flash Attention

Optimizations committed in bf8423204 and ecaac4459 vectorize 64-bit and 128-bit memory transactions for TurboQuant KV cache in fattn-vec.cuh. Normalization scaling is hoisted out of the inner loop, and sign unpacking is streamlined, minimizing shared-memory conflicts and register spills.

3. Shared Activation Quantization in MMQ

Commit 6c410ea8c introduces a per-graph shared Q8_1 activation cache for MMQ matrix multiplies. Multi-head projection layers (such as gate and up projections) reuse the exact quantized activation copy instead of re-quantizing on device, boosting prefill to 238.76 t/s (+11.6% over Upstream).

4. Pinned Host Memory & Direct PCIe DMA

Commits fd2f054b2 and eb97dfa02 register host-allocated buffers with hipHostRegister. Both MoE expert upload streams and host-backed KV spill cache utilize asynchronous DMA transfers, eliminating synchronous host-device stalls during context scaling and generation.

5. Native FP16 Fast Walsh-Hadamard Transform

Commit 08363462f adds a native FP16 Fast Walsh-Hadamard Transform (FWHT) kernel to turbo-wht.cu. Half-precision vector operations (half2) perform the 128-point orthonormal rotation in registers before quantization, cutting WHT transformation latency by over 40%.

6. TurboQuant Orthonormal KV Cache Compression

Standard F16 KV cache consumes ~177 MiB per 1,000 tokens, causing severe PCIe memory spill above 12k tokens on 16GB cards. TurboQuant compresses 64k context KV footprint to just 1,637 MiB, enabling 65,536+ tokens with over 1 GB free VRAM headroom remaining on the RX 9060 XT.

Synchronous Profile Pre-Seeding

Standard LRU MoE caching suffers from a cold-start penalty where the first 50-100 tokens experience 100% cache misses, stalling generation. By loading top hot experts from data/expert-profile.bin before token 0, cache hit rate starts immediately at ~70%+, ensuring responsive real-time generation from the very first token.

Safe Host Memory Pinning Guard

Host memory pinning enables direct DMA transfers across PCIe. Our dynamic memory guard enforces a 4 GiB unpinned physical RAM margin (via GlobalMemoryStatusEx on Windows and sysinfo on Linux). If pinning would leave less than 4 GiB free, pinning is safely disabled to prevent OS memory exhaustion, driver freezing, and system crashes.
